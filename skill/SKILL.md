# Jira

CLI `jira` уже настроен (адрес — `jira url`, токен в системном хранилище). Если команда отвечает «адрес Jira не задан» или «нет токена» — попроси пользователя самого выполнить `jira login` (токен вводит только он). Вывод компактный — не добавляй `--json`, если не нужно парсить.
`--json` есть только у `me`, `ls`, `q`, `sprint`, `show`, `report`; команды записи (`log`, `estimate`, `comment`, `move`, `assign`, `create`) с `--json` падают с «неизвестный флаг --json» и ничего не отправляют.
`show --json` содержит `resolved` (`""` если не закрыта), `parent: {key, summary}` (если есть), `description_truncated` (описание обрезано до 4000 символов — повтори с `--full`), `comments` — всегда массив.

`jira vi` — интерактивный экран (список и канбан) для человека; без терминала он завершается ошибкой, поэтому сам его не запускай — пользователю можно его подсказать.

## Правила

1. **По умолчанию только задачи пользователя.** Задачи других исполнителей (`--user`, JQL по чужому assignee) — только если пользователь явно попросил. `--user U` проверяет username в Jira: опечатка — ошибка «пользователь U не найден», а не пустой список; `none` (без исполнителя) — только в `create --assignee none` и `assign KEY none`, не в `--user`. Исключение — спринт: `jira sprint now|active|ID` показывает задачи всей команды (так решил пользователь), свои — `--user me`.
2. **Запись — только по явной просьбе пользователя**, никогда по своей инициативе: `log`, `estimate`, `comment`, `move`.
3. **`create` и `assign` — в два шага:** запусти без `--yes`, покажи превью пользователю, дождись явного «да», только потом повтори ту же команду с `--yes`. Превью проверяет исполнителя в Jira и показывает его как `username (Display Name)`; несуществующий username — ошибка уже на превью.
4. Исполнителя меняй только на username, который назвал пользователь. Не угадывай.
5. Проект при создании называет пользователь. Тип — тоже, если назвал; иначе не передавай `--type`: возьмётся тип по умолчанию (`jira type` его показывает, превью — тоже). Если Jira отвечает, что такого типа нет, — спроси тип у пользователя и передай его в `--type`. Не создавай подзадачи и пачки задач.
6. **Настройку не трогай:** `jira login`, `jira logout`, `jira url АДРЕС`, `jira type ТИП` выполняет только сам пользователь. Смотреть можно: `jira url`, `jira type`.

## Команды

```
jira me                                  # проверить токен → username<TAB>Имя
jira ls [--all] [--project P] [-n 30]    # мои незакрытые (--all: и закрытые)
jira ls --user U                         # чужие — только по просьбе
jira q 'JQL' [-n 30]
jira sprint [--project P]                # активные спринты: ID НАЧАЛО КОНЕЦ ФАЗА ДОСКА NAME
jira sprint now [--project P] [--user U] [--open] [-n 30]   # задачи текущих спринтов
jira sprint active [--project P] [--user U] [--open] [-n 30] # задачи всех активных, и просроченных
jira sprint ID [--user U] [--open] [-n 30]                  # задачи спринта по номеру из списка
jira show KEY [--comments 3] [--full]
jira move KEY                            # список переходов
jira move KEY "в работе"                 # по имени перехода/статуса, без регистра
jira comment KEY "текст"                 # или текст через stdin: jira comment KEY -
jira log KEY 1d 4h "что сделал" [--date YYYY-MM-DD]   # время: 1d 4h, 1d4h, 2h30m (w d h m); дальше — комментарий
jira estimate KEY 1d 4h                  # Original Estimate; после KEY — только длительность
jira create --project P --summary S [--type T] [--desc D|-] [--estimate 4h] [--assignee U|me|none] [--yes]
jira assign KEY U|me|none [--yes]        # превью: исполнитель как username (Display Name)
jira report [YYYY-MM] [--project P] [--user U] [--by day]
```

Аргументы проверяются до запроса к Jira: лишний или пустой аргумент, неизвестный или повторённый флаг, флаг без нужного значения, пустое значение флага или значение не того формата (`--assignee ""`, `-n 0`, `--date 2026-13-01`) и `--yes=…` — ошибка, ничего не отправляется. Текст, начинающийся с «-» (комментарий, JQL), — после `--`: `jira comment KEY -- "-1 баг"`, или через stdin.

Вывод `ls`/`q`: `KEY  STATUS  ESTIMATE  SPENT  SUMMARY` (TSV, `-` = пусто). Последняя строка `# показано N из M` — значит есть ещё.

`sprint`: «текущий» спринт (`now`) — активный, у которого сегодняшняя дата от даты начала до даты конца включительно (по локальному времени: в день конца он ещё текущий). Активный с прошедшей датой конца — «просрочен» (его не закрыли в Jira), в `now` не попадает: его задачи — `jira sprint ID` или вместе со всеми активными — `jira sprint active`. Текущих бывает несколько — `now` и `active` выводят каждый: строка `# ID NAME · начало – конец · фаза`, под ней задачи как в `ls`; `-n` — на каждый спринт. `--project` выбирает доски проекта и оставляет задачи только этого проекта. `--user`, `--open`, `-n` — только с `now`, `active` или номером. Доска, на которой Jira ответила ошибкой, пропускается: `# предупреждение: доска N (…) пропущена: …` в конце. Нет текущего спринта — `now` завершается ошибкой: в ней активные спринты с фазами, подсказка (`jira sprint ID` или `jira sprint active`) и пропущенные доски — текущий мог быть на них; `active` без спринтов — `# нет активных спринтов`, не ошибка. В `--json`: `warnings` — всегда массив; в списке `sprints[]` — `board`, `board_id`, `id`, `name`, `start`, `end`, `goal`, `phase` (`current`, `overdue`, `not_started`, `undated`, `future`, `closed`); в задачах `sprints[]` — те же `id`, `name`, `start`, `end`, `goal`, `phase` и `issues`, `total`.

Время на ввод (`log`, `estimate`, `--estimate`) — формат Jira: `30m`, `2h`, `1d 4h` (1d = 8h).
Время в выводе (`ls`, `q`, `show`, `report`) — всегда часы и минуты: `8h`, `2h30m`, `30m`, `-` = пусто; дней нет (оценка `2d` показывается как `16h`). В `--json` — числа в часах: `estimate_h`, `spent_h` (+ `remaining_h` в `show`), `0` = пусто.

`report`: задачи, закрытые пользователем в месяце, + задачи, куда он списывал время в месяце; других строк нет. Месяц — по локальному времени (задача, закрытая 1-го в 02:00 по +05, — в этом месяце, хотя по UTC это прошлый). Колонки `KEY ОЦЕНКА СПИСАНО ЗАКРЫТА STATUS SUMMARY`; «оценка закрытых» в итоге — сумма оценок только закрытых в месяце задач. `--by` принимает только `day` (разбивка списанного по дням); `--by issue` нет — по задачам это вывод без `--by`. Записи с неразборчивой датой не теряются молча: строка `# предупреждение: записей с неразборчивой датой: N (KEY, …)` в конце; в `--json` (оба режима) поле `warnings` — всегда массив строк, `[]` если всё в порядке.

## Новая задача

Summary — одно предложение, что сделать. Оценку (`--estimate`) ставь, только если пользователь её назвал. Исполнитель по умолчанию — сам пользователь.

Многострочное описание передавай через stdin:

```
printf '%s\n' 'строка 1' 'строка 2' | jira create --project PROJ --summary "..." --desc -
```
